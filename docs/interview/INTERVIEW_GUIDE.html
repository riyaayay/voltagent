"VoltAgent is a voice-first, bilingual copilot for EV charger field technicians working on live high-voltage equipment. The 5 Limitations to Volunteer Upfront

  1. In-Process Evaluation: Elasticsearch 8.15.1 and Qdrant v1.11.3 adapters are implemented, but all metrics derive from local in-process BM25 (rank-bm25) and PyTorch cosine search.
  2. Unreviewed Hindi Lexicon: Devanagari numeral conversions and Hindi technical unit mappings are unreviewed by a native Hindi electrical engineer.
  3. Table Dilution (Why 8/10, not 10): Verifier misses cases where both true and false values appear in adjacent rows of the same table chunk (W01, W02).
  4. No End-to-End Latency Table: Local component latencies are measured (180–360 ms), but live network latency percentiles under Gemini API load are NOT IN REPO.
  5. Browser Mic Dependency: Web Speech API requires Chrome/Edge on localhost or HTTPS; mobile field use requires a dedicated STT SDK.

Section B: Problem, Safety Contract, and Pitch

In commercial DC fast charging (400V–1000V DC at up to 500A), technicians work wearing heavy Category III/IV insulated gloves and arc-flash face shields. Navigating a 500-page PDF on a smartphone while probing electrical leads is dangerous. However, standard LLMs hallucinate numbers fluently: turning a 10-minute capacitor discharge wait into 10 seconds or 2.8 Nm into 2.8 kilograms. A confident wrong answer is catastrophic.

Section C: Step-by-Step System Architecture

Architectural Deep Dive

1. Query Normalization & Token Invariant (query_agent.py): Spoken queries often fragment error codes (e.g. "E 101" or Devanagari "ई-१०१"). The query agent normalizes them to canonical E101. Under F-006, if reformulation drops an error code or model designator, the rewrite is rejected and the raw query is used.

2. In-Process Dual-Leg Hybrid Retrieval (hybrid.py): Dispatches in parallel to lexical BM25 (token-exact for OCPP messages like TransactionEventRequest) and dense multilingual embeddings (paraphrase-multilingual-mpnet-base-v2). Combined using Reciprocal Rank Fusion ($k=60$). If either leg crashes, the healthy leg executes alone without throwing a 500 (F-005).

3. Dual-Layer Verification (verifier_agent.py & numeric_gate.py): Evaluates answers sentence by sentence. Layer 1 uses pure regex deterministic gating across full chunk text for voltages, currents, delays, torque, and error codes. Layer 2 checks auxiliary verb negation conflict. Layer 3 evaluates multilingual cosine similarity against cited chunks (threshold 0.55). Layer 4 isolates specific error code subpassages to prevent table dilution.

Section E: Exhaustive Codebase Walkthrough

Core Framework (voltagent/)

voltagent/config.py: Central Pydantic BaseSettings with extra="ignore". Non-obvious design: Every parameter defaults to zero-dependency local equivalents (sparse_backend="bm25", cache_backend="memory") so the repo boots immediately upon clean clone without external services.

voltagent/llm.py: Interface protocol for LLMClient supporting Gemini, OpenAI, and FakeLLMClient. Non-obvious design: Contains 5-attempt exponential backoff specifically handling Gemini HTTP 429 quota exhaustion.

voltagent/cache.py: Response caching for Outcome A. Non-obvious design: Injects a SHA-256 corpus_version_hash into the cache key. When PDFs are updated or re-indexed, cached answers auto-invalidate fleetwide without manual flushes (F-008).

Orchestration & Verification (voltagent/agents/)

voltagent/agents/graph.py: StateGraph compilation. Non-obvious design: Top-level try/except wraps execution into typed Outcome C rather than letting 500 tracebacks leak to the field technician.

voltagent/agents/numeric_gate.py: Pure regex deterministic parser. Non-obvious design: Maps Devanagari numerals (०-९ $\to$ 0-9) and transliterated Hindi electrical terms (किलोवाट $\to$ kW), enforcing exact magnitude preservation without lossy conversions.

voltagent/agents/verifier_agent.py: Multi-stage verifier. Non-obvious design: Isolates error-code subpassages and strips lead-in boilerplate, checking cosine similarity of the core meaning rather than whole-chunk topical vector.

Ingestion & Retrieval (voltagent/ingestion/ & retrieval/)

voltagent/ingestion/loaders.py: Robust PDF page loader. Non-obvious design: Detects corrupted PUA font encodings (F-025) and strips repetitive cross-page running headers/footers (F-026).

voltagent/retrieval/fusion.py: Reciprocal Rank Fusion implementation. Non-obvious design: Standardizes rank position via $1 / (60 + r)$, fusing incompatible BM25 scores and cosine similarities without score calibration.

voltagent/retrieval/hybrid.py: Dual-leg search coordinator. Non-obvious design: Implements per-leg fault isolation: if one leg fails, the other returns results and logs degradation (F-005).

Why 8 of 10, Not 10: Multi-Row Table Dilution

The Root Cause: W01 and W02 failed due to table dilution. In W01, the chunk defines both Yellow (locked) and Red (error). When the claim said Yellow means error, the word "error" appeared in the chunk, and sentence-transformers cosine similarity against the whole status table was 0.706. In W02, the physiological table lists 1 mA, 5 mA, and 50–150 mA. The claim stated 50 mA; numeric_gate.py saw "50 mA" in the chunk's range, so the gate passed, and whole-table similarity was 0.735.

Why We Refused to Special-Case It: Adding "yellow" or "red" to numeric_gate.py would pass W01 on this test set, but leave table dilution unaddressed. The true engineering fix is row-level chunking or cross-encoder NLI reranking.

F-022 in Plain Language: The multilingual embedding model truncates text after 128 wordpieces. In our initial pipeline, chunks were 350 tokens, making the tail of every chunk invisible to dense search. Re-chunking to 100 tokens aligned chunks with the embedder window, directly boosting Hindi Devanagari recall from 71.4% to 85.7%.

The MRR Trade-Off: Smaller chunks tripled the corpus index from 1,641 to 4,857 chunks. This improved Recall@5 to 97.9% (safety priority: supporting text is in top 5), but slightly diluted MRR from 0.920 to 0.903 as adjacent chunks competed for rank 1.

Section I: 40+ Technical & Hostile Interview Q&As

Group 1: Fundamentals

Q1: Why hybrid search instead of pure dense vector search?

30-Second Answer: Field technicians search across two opposite modalities: exact alphanumeric identifiers (e.g. error code E208, OCPP message TransactionEventRequest), which BM25 excels at, and cross-lingual descriptive symptoms (Hindi "चार्जर चालू नहीं हो रहा"), which require dense multilingual embeddings. Lexical search has a 0.0% recall on Hindi Devanagari, but achieves 100% on exact English codes. Hybrid RRF fusion achieved 97.9% recall across both.

Don't Say: "Dense search is modern so we just kept BM25 as an old fallback."

Q2: What is Reciprocal Rank Fusion, and why use k=60?

30-Second Answer: RRF merges ranked candidate lists by summing $1 / (k + r_i(d))$. BM25 scores are unbounded positive numbers based on IDF, while cosine similarities range from -1 to 1. Calibrating score distributions across languages is brittle. RRF operates purely on ordinal ranks. We set $k=60$ per Cormack et al. (2009) to prevent top outliers from dominating the fused ranking.

Q3: Why not use a fine-tuned model instead of RAG?

30-Second Answer: Fine-tuning bakes factual numbers into static weights that cannot provide sentence-level PDF page citations, cannot be updated instantly when a manufacturer issues a service bulletin, and still hallucinate under pressure. RAG separates static reasoning from dynamic, verifiable ground truth.

Group 2: Project-Specific & Hostile Pushback

Q4: "You claim 8/10 on wrong cases. Is 10 cases statistically meaningful?"

How to Answer: "No, 10 cases is not a statistical sample; it is a qualitative, frozen adversarial smoke test across 10 distinct failure modes. That's why we subsequently evaluated heldout_60.json—a completely unseen set of 60 cases across 44 real PDF sources—where the verifier flagged 27 of 30 wrong cases (90.0%) with a 13.3% false-flag rate on correct guidance."

Q5: "Your README lists Elasticsearch and Qdrant, but Docker didn't run. Did you fake results?"

How to Answer: "Not at all. We explicitly document in docs/RESULTS.md that all benchmark numbers reflect in-process execution (rank-bm25 and PyTorch exact cosine retrieval). The production cluster adapters are fully implemented in code, but our dev environment was a Windows host without Docker. The retrieval mathematics are identical, and our setup script guarantees anyone can reproduce our exact numbers on a bare laptop."

Q6: "What happens when the LLM service goes down?"

How to Answer: "The pipeline never crashes or returns an unhandled 500 error. The LangGraph error boundary intercepts the exception, records degraded_stages=['llm'], and returns typed Outcome C. The technician is told explicitly that the system cannot answer right now and is advised to follow on-site safety procedures."

Group 3: ChargePoint Role-Fit

Q7: "How would you scale this to 10,000 active technicians?"

30-Second Answer: Deploy stateless FastAPI pods on Kubernetes behind an ingress controller, point sparse search to an Elasticsearch cluster, point dense search to distributed Qdrant nodes, and switch ResponseCache to a Redis cluster. High-frequency diagnostic queries are served in <10 ms from Redis without invoking LLM or vector search.
